## Refactoring Goals

### Separation of Concerns
- Extract verification logic from Verifier class into specialized modules
- Separate prover implementations into a unified prover interface
- Move Lean-specific verification into core verifiers module

### Configuration-Driven Design
- Replace hardcoded configurations with configurable experiment classes
- Create reusable experiment configurations for different datasets and models

### Improved Data Flow
- Unify data loading logic into a consistent interface
- Create a modular and testable pipeline for trace collection

### Better Error Handling and Logging
- Replace print statements with proper logging
- Improve timeout handling
- Add better error recovery for Lean verification failures

### Testing Infrastructure
- Add unit tests for core verification and proving logic
- Integration tests for the full SAFE pipeline
- Mock interfaces for external dependencies

## Migration Strategy

1. **Phase 1**: Create new directory structure and base classes
2. **Phase 2**: Migrate core verification logic while maintaining backward compatibility
3. **Phase 3**: Refactor data loading and experiment scripts
4. **Phase 4**: Add comprehensive testing and documentation
5. **Phase 5**: Remove deprecated files and finalize API

## Benefits

- **Modularity**: Each component has a single responsibility
- **Testability**: Clear interfaces make unit testing easier
- **Extensibility**: Easy to add new provers, verifiers, or datasets
- **Maintainability**: Cleaner separation makes debugging and updates simpler
- **Configuration**: Experiment parameters are centralized and reusable
